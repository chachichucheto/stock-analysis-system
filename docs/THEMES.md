## 0. このリストの使い方

- ここに載っているのは**テーマ**(背景)であって、シナリオではない。テーマに関するニュースの多くは、テーマの温度を更新するだけで終わる。シナリオを立てるのは、S級・A級の新しい事実が出たときだけである(`CONCEPT.md` §1.4)。
- 各テーマには、フェーズ2で**前提カード**(市場が今何を想定しているか)を作る。前提カードはサプライズを判定する基準線になるため、一次情報を確認できるローカル環境で作る。
- 各テーマの関連銘柄は**このファイルには載せない**。§4 の手順で、銘柄マスタと照合しながらローカルで作る。

## 4. 局面展開型のひな形(テーマではなく、突発事象の型)

大地震のような突発事象は、テーマではなく**局面展開型のシナリオ**として扱う(`CONCEPT.md` §1.2)。いざ起きたときに慌てないよう、局面と起動条件のひな形だけを先に用意しておく。

| ID | 型 | 局面の例 |
|---|---|---|
| E01 | 大地震・大災害 | パニック(全面安)→ 冷静化(防災・代替生産)→ 復興予算 → 実需 |
| E02 | 感染症の流行 | 初期の混乱 → 衛生・検査・巣ごもり → 収束・再開 |
| E03 | 戦争・軍事衝突 | 急落 → 防衛・資源・海運 → 長期化 or 停戦(復興) |
| E04 | 政変・選挙 | 観測 → 結果 → 政策の具体化 |
| E05 | 金融危機・急落 | 投げ売り → 下げ止まり → 反発の主役の入れ替わり |

各ひな形の局面ごとの起動条件は、フェーズ2で具体化する。

## 6. 関連銘柄の作り方(このファイルに銘柄を載せない理由)

調査の過程で、LLMが銘柄コードを誤る実例が出た(ある証券会社のコードを別の銀行のコードとして記載していた)。テーマと銘柄の対応は、次の手順でローカルで作る。

1. 候補の出典:株探などのテーマページ(利用規約上可能な場合)、有価証券報告書のセグメント、LLMの提案
2. **銘柄マスタとの照合**:銘柄コードと社名の両方が一致したものだけを登録する(`DESIGN.md` §5.5)
3. テーマ純度(その事業の売上比率)は、有価証券報告書で確認できたものだけ数値を入れる

## 7. リストの更新ルール

- **追加**:`CONCEPT.md` §1.5 の「誕生の兆候」が2つ以上そろったら、段階を「誕生」として**仮登録**する。兆候は次の4つ。
  - 既存テーマに当てはまらないS・A級のニュース
  - 新しい言葉の急増
  - 説明のつかない連れ高
  - 人気テーマへの新しい名前の出現
- 仮登録のテーマが拡散の段階まで育ったら、本登録する。育たずに消えたものも記録として残す。
- 各テーマには段階(誕生・拡散・主流・成熟・冷却)を付ける。本リストの初期テーマは、ほとんどが主流・成熟の段階にある。
- **休止**:温度が「冷却中」のまま半年続いたテーマは休止にする。削除はせず、復活できるようにする。
- 追加・休止は、日付と理由を付けてこのファイルに追記する。

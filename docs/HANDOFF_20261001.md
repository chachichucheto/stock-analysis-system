## 6. 罠・既知の問題(実測)
- **既存の2つの株価ファイルは分割調整が食い違う**(555銘柄中185銘柄)。`layered_prices` がつなぎ目で倍率補正する。**既存の日足は7/24で止まっている**ので、古い値を黙って使わない設計(10日以上古ければ自動補完→だめなら「データなし」)。
- **日本語パスの仮想環境だと yfinance が SSLError**(`certifi` の証明書パスが非 ASCII)。`netfix.py` が CLI 起動時に自動で対処。CLI を通さないスクリプトから `fill_gap` 等を呼ぶときは `ensure_ascii_ca_bundle()` を先に呼ぶ(`fill_gap` は内部で呼ぶ)。
- TDnet の HTML: `class` が2語、銘柄コードは5桁(ETF は5桁目が0でない)。**取得0件でも「成功」と記録される**ので、平日の件数を必ず確認する。
- **Google News は一時的に404を返すことがある**(2026-10-01 0:00 に最初のキーワードで発生し、以前は20キーワード全体が失敗していた)。→ 1キーワードの失敗で全体を止めない形に修正済み(失敗したキーワードは `fetch_log` の `google_news:<語>` に記録)。RSS・GDELT・EDINET なども同様に、一部の失敗で全体を止めない。全部が失敗したときだけ、収集の失敗として扱う。
- **時限式のテストに注意**:テストが「実際の今日」に依存すると、日付が変わった午前中だけ失敗する(`tests/test_e2e.py` で実際に発生。DAY0 を過去の固定日にして解決)。日付を扱うテストは、実際の今日より前の固定日にする。
- DuckDB は**同時に1プロセスしか書き込めない**。自動収集と手動操作が重なると最大120秒待つ(コマンドが長く止まることがある)。共有棚(Parquet)は、この衝突を避けるための出力。
- `WebFetch` は TDnet・JPX を 403 で弾く。開示の原本(PDF)は、この PC から直接取得し(`requests`、システムの Python の `pypdf`)、テキストを読む。Google News のリンクは中継 URL で開けないことが多い(見出しで検索して元記事を探す)。
- 予行演習で、開示がニュースに構造的に負ける問題が見つかり、開示の別枠(最大3件)で解決済み。TDnet を1か月分まとめて取り込んだ分は `first_observed_at` が取り込み日(初日のパックに混ざった。初回のみ)。
- 既存リポジトリでは、別セッションが `design_rise_capture.md` などをステージしていた。**自分のファイルだけをコミットする**。
- 研究系の重い計算が並行して走ることがある(CPU)。連想側の重い処理の前に確認する。
- Claude の Web 検索は1セッション200回の上限。夜の手順は予算(15+10+5回)を守る。

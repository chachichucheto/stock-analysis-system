# 割安カタリスト・モデル 設計書 v0.1

- ステータス: **クラウド側の設計・実装は完了。実データでの検証と運用はローカル**(`VALUE_LOCAL_KICKOFF.md`)
- 位置づけ: 既存の3モデル(ファンダメンタルズ / 需給 / ニュース連想)に続く4つ目。連携は CSV の受け渡しだけ
- 根拠: `INVESTOR_RESEARCH.md`(投資家の手法調査)、`VALUE_CATALYST_PLAN.md`(最初のたたき台)
- コード: `src/assoc/value/`、コマンド: `python -m assoc value <check|screen|commit|report|backtest|eval>`

> **注意**:数値の閾値は、有名投資家の手法を**検索結果の要約**から拾った初期値で、本人の一次情報で確認できていない(`INVESTOR_RESEARCH.md` §0)。
> 閾値のコメントに「△」が付くものは特に弱い。**過去検証(§9)を通るまで、運用に使わない。**

## 1. 目的とゴール

> **資産に対して明確に割安で、かつ数か月以内に再評価のきっかけがありそうな小型株を、根拠付きで上位に挙げる道具。**

- 道具である。最終判断は常にあなたが行う。自動売買はしない。売買の指示も書かない。
- ゴールは連想モデルと同じく**探す能力**。売買成績(約定、利確のタイミング)は評価しない。
- 「動いた」の定義(**運用前に固定。後から変えない**):基準日の終値から最長 **20営業日** の間に、TOPIX を **+10%** 以上上回った(`ValueThresholds.horizon_days` / `moved_excess`。連想モデルと同じ)。
- 合格の判定は、**ベースライン(同じ日・同じ足切りを通った全銘柄)との比較**で行う。TOPIX との比較ではない。型の効果だけを見るため。

### 1.1 運用前に固定する合格基準

**`docs/VALUE_VALIDATION.md` §5 に移した(事前登録の仮説 H1〜H5、打ち切りの基準、「勝てる」と提案できる条件)。** そちらが正。要点:

- 判定に使うのは、事前に決めた**主セル**だけ(型A×120営業日、型B×250営業日、型C×60営業日、型D×20営業日、型の重なり×120営業日)。日付ごとの差の t>2 を、前半・後半の**両期間で**。
- H1〜H4 のうち**2つ以上**が合格し、取引コスト後も超過リターンが残り、開示読解が G3(本物30件で重大な取り違え10%以下、引用の照合率100%)を満たすまで、**出力は「研究用の候補」であり、「勝てる候補」ではない**。
- 閾値の調整で通さない。調整するなら、別期間で再確認する。
- **検出力の限界**:基準日24(約2年の月次)では、20営業日で+2%以上の優位性しか確実には検出できない(`scripts/value_power_analysis.py`)。「差なし」は「優位性なし」を意味しない。

## 2. 優位性と、狙わないもの

| 源泉 | 中身 |
|---|---|
| ① 機関が入れない規模 | 時価総額が小さく流動性が薄い銘柄は、大口が買えず調査もされない |
| ② 開示の読み込み | 適時開示・決算の全件読みは人間には重い。LLM が得意(片山氏の優位性の再現) |
| ③ 下値の限定 | ネットネット・PBR割れは、悪くても資産価値が下値の目安になる(かぶ1000氏・たーちゃん氏) |

**狙わないもの**:テーマ株の短期の値幅取り(連想モデルの領域)、板読みの超短期(cis氏・テスタ氏。再現に執行の速さと裁量が要る)、大型株、信用の高レバレッジ。

## 3. 全体像

```
[ローカルが用意するデータ]            [機械(Python)]                [LLM(Claude Code)]
 universe.csv  銘柄マスタ ─┐
 financials.csv 財務(開示日つき)─┼→ check  データの点検
 株価DB(既存)             ─┤
 TDnet 開示(収集済み DB) ──┘
                              ├→ screen  型A・B・C・D → 足切り・危険信号
                              │        → pack_YYYY-MM-DD.json ─────→ 開示を読む
                              │                                    (value-disclosure-v1.md)
                              │                                    → inbox/value_YYYY-MM-DD.json
                              ├← commit  検証(引用が文面にあるか)→ 追記専用の記録
                              └→ report  合議スコア → レポート・連携 CSV
                              └→ backtest  過去検証(先読み・生存者の罠を構造で防ぐ)
```

- **機械の部分**(スクリーン・スコア・損失の限定・過去検証)は、すべて純粋な関数で、合成データのテストがある。
- **LLM の部分**は「開示を読んでカタリストの有無と強さを判定する」だけ。数字の計算はさせない(型に該当した根拠は機械が出す)。
- LLM の出力は、引用が入力の文面に**そのまま含まれる**ことを機械が照合する(推論は証拠でない。DECISIONS D04 と同じ規律)。

## 4. 主なデータ構造(`value/models.py`)

| 名前 | 役割 |
|---|---|
| `FinancialRow` | 1回の決算開示。**`disclosed_date`(開示日)が先読み防止の要**。貸借対照表は期末の値、損益は直近12か月(TTM) |
| `UniverseRow` | 銘柄マスタ。上場日・**上場廃止日**を持つ(上場前・廃止後は母集団に入れない) |
| `Snapshot` | ある日(asof)に知り得る情報の束。株価は asof 以前だけ、財務は開示日が asof より**前**のものだけ |
| `ScreenResult` | 型ごとの該当/非該当、根拠の数字(`facts`)、文章の根拠(`reasons`)、足りなかったデータ(`missing`) |
| `Candidate` | 銘柄ごとの型・危険信号・カタリスト・スコア |

**データが足りないときは「該当しない」とし、`missing` に書く。推測で通さない。**

## 5. ローカルが用意するデータ(形式)

置き場所:`data/value/`(config の `value.dir` で変更可)。**git に入れない**(`.gitignore` の `data/`)。金額はすべて**円**。日付は `YYYY-MM-DD`。文字コードは UTF-8(BOM 付き可)。

### 5.1 `universe.csv`(銘柄マスタ)

| 列 | 必須 | 内容 |
|---|---|---|
| `code` | ○ | 銘柄コード(4桁。株価DBと同じ表記) |
| `name` | ○ | 社名 |
| `market` | ○ | 市場区分 |
| `sector33` | ○ | 東証33業種の名称(型Dの業種別の閾値に使う) |
| `listed_date` | ○ | 上場日。不明なら空(警告) |
| `delisted_date` | | **上場廃止日。上場廃止銘柄を必ず入れる**(生存者バイアスの防止) |
| `monitoring` | | 監理・整理ポスト 1/0(**現在の状態。過去検証では使わない**) |
| `going_concern` | | 継続企業の疑義 1/0(同上) |

### 5.2 `financials.csv`(財務データ。1行=1回の決算開示)

| 列 | 必須 | 内容 |
|---|---|---|
| `code`, `period_end`, `disclosed_date`, `period` | ○ | `period` は `FY`/`Q1`/`Q2`/`Q3`。**`disclosed_date` は実際の開示日**(TDnet の開示日。期末+決算日の推定で埋めない) |
| `cash` | | 現金及び預金 |
| `receivables` | | 受取手形及び売掛金 |
| `securities` | | 有価証券(流動資産) |
| `investment_securities` | | 投資有価証券 |
| `allowance` | | 貸倒引当金(**正の数**) |
| `current_assets`, `total_assets`, `total_liabilities`, `equity` | | 流動資産、総資産、負債合計、純資産 |
| `interest_debt` | | 有利子負債(借入金+社債など) |
| `revenue_ttm`, `operating_income_ttm`, `net_income_ttm` | | **直近12か月**の売上・営業利益・純利益(四半期なら累計から計算) |
| `shares_ex_treasury` | | 発行済株式数(自己株式を除く) |

- **同じ期の訂正開示は、行を足す**(同じ `period_end`・`period` で `disclosed_date` が新しいもの)。読み出しは「asof より前に開示された最新版」。
- 取得元の候補(無料):EDINET の有価証券報告書・四半期報告書(XBRL)、決算短信。**どの項目がどこから取れるかはローカルで確認する**(`VALUE_LOCAL_KICKOFF.md` フェーズB)。
- 株価は既存の株価DB(`prices`)を使う。**TOPIX(または 1306)と、上場廃止銘柄の株価が残っているか**を確認する。

### 5.3 点検:`python -m assoc value check`

開示日が期末より前、株式数が0以下、コードの重複(エラー)/上場廃止銘柄が無い、欠損が多い項目、株価のない銘柄(警告)を出す。**過去検証の前に必ず通す。**

## 6. 計算(`value/screens.py` ほか)

### 6.1 母集団の足切り(段階1。`snapshot.passes_base`)

時価総額 30〜500億円、売買代金(20日平均)3,000万円以上、株価100円以上、開示済みの財務データがあること。

### 6.2 4つの型

| 型 | 元の投資家 | 条件(初期値) | 備考 |
|---|---|---|---|
| **A 資産バリュー** | かぶ1000氏・たーちゃん氏 | ネットネット指数 < 1、または PBR < 0.5 かつ 自己資本比率 ≧ 60% | ネットネット指数 = 時価総額 ÷(現預金+売掛金+有価証券+**投資有価証券**−貸倒引当金 − 総負債)。分母が0以下なら非該当。保守版(売掛金×0.8、投資有価証券×0.7)も `facts` に併記 |
| **B シクリカル底** | たーちゃん氏 | 本決算5期以上で赤字1期以上・黒字2期以上 かつ いま赤字 かつ 株価がピーク(約5年)から-2/3 以下 かつ 自己資本比率 ≧ 30% かつ 有利子負債 ≦ 現預金+有価証券 | 「潰れない」の確認が核 |
| **C 成長の初動** | 片山氏・ぱりてきさす氏 | 時価総額 ≦ 300億円、営業利益(12か月)の前年比 ≧ +20% かつ 前の期より加速、PER ≦ 15倍、直近10日に出来高が直前20日平均の2倍以上の日、60日で +50% を超えて上がっていない | 「損切りしなくて済む位置で買う」(片山氏)を、急騰済みの除外で表現 |
| **D 売られすぎ反発** | BNF氏 | 25日線からの下方乖離が業種別の閾値以下(既定-20%、電気機器など-20%、証券・銀行-15%、医薬品・食品-12%) | **単独では候補にしない**。A〜C のどれかと重なったときだけ+1 |

### 6.3 危険信号(`dangers.py`)

- **除外(block)**:債務超過、監理・整理(現在の状態)、継続企業の疑義(同)、発行済株式数が前年から30%超増加
- **警告(warn。1つにつき-1点)**:発行済株式数が10〜30%増加、赤字で有利子負債が現預金の3倍超、直近20日で+50%超の急騰

### 6.4 合議スコア(`score.py`)

```
スコア = 型の一致数(A・B・C+Dの補助) + カタリスト点(Strong 2 / Medium 1 / Weak 0.5) − 警告の数
候補の条件 = 除外なし かつ (型が2つ以上 または (型が1つ以上 かつ カタリスト点 ≧ 1))
```

順位は、スコア → 型の数 → コードの順で決める(同じ入力なら毎回同じ結果)。レポートは上位10銘柄まで。

### 6.5 損失の限定(`risk.py`)

銘柄選択とは別に、**先に**決める(どの投資家も共通。`INVESTOR_RESEARCH.md` §2.1 C4)。判断材料を出すだけで、指示ではない。

- 株数 = min(総資金×0.75% ÷ 1株の損失、20日平均売買代金×5% ÷ 株価、総資金×20% ÷ 株価) を単元株で切り捨て
- 損切りの目安 = 直近20日の安値の2%下(損切り幅が25%を超える銘柄は「見送り」)
- 同時保有の損失合計は総資金の5%まで(`portfolio_check`)
- 運用上の損切りは3種:価格・時間・**理由**(カタリストの消滅。最優先。かぶ1000氏)。**「理由」の判定は人が行う**(コードにはまだ無い)
- 総資金は config の `value.capital_yen`(0なら株数の上限を出さない)

## 7. 手順と成果物

| コマンド | 内容 | 成果物 |
|---|---|---|
| `value check` | データの点検 | 標準出力 |
| `value screen [--date]` | スクリーン、LLM に渡す入力パックの作成。機械だけの候補を追記専用で記録(重複しない) | `data/value/pack_YYYY-MM-DD.json`、記録 `value_candidate` |
| (LLM)`/value-daily` | `prompts/value-disclosure-v1.md` に従って開示を読む | `data/value/inbox/value_YYYY-MM-DD.json` |
| `value commit [--file]` | 出力を検証して記録に追記。**引用が開示の文面に無ければ全体を差し戻す** | 記録 `value_catalyst` |
| `value report [--date]` | 合議スコアでランキング、レポート、連携ファイル | `data/reports/value_*.md`、`data/export/value_*.csv` |

- 入力パックは、同じ日に作り直さない(その日に LLM が読んだ内容と、確定時の照合元を変えないため)。データを直して作り直すときは、パックのファイルを消してから実行する。
- 連携ファイルの列:`date, code, name, score, types, catalyst_strength, price, stop`。他のモデル(需給・ファンダメンタルズ)は、これを読むだけで連携できる。

## 8. 開示読解と評価(`catalyst.py`、`evalset.py`)

- カタリストは6つの型(株主還元 / 資産・資本 / 株主の動き / 業績 / 市場区分・指数 / 事業)と強さ(None/Weak/Medium/Strong)、時期で出す。
- **反対仮説(`bear_case`)は、カタリストがある銘柄では必須**(強化と弱体化の両方を出させる)。
- 評価セット(`knowledge/value_eval/`):開示の原文と、事後の株価の動きから決めた正解。**成功例と、動かなかった例を同数にする。**
- 評価指標:種類の適合率・再現率、強さの一致、**重大な取り違え**(Strong/Medium を None と答えた、またはその逆)、反対仮説の有無、**引用の照合率**。
- `fictional: true` の事例は、形式の見本と評価器の自己テスト用。**本番の精度には数えない**。本物はローカルで作る。
- LLM の精度は、過去の開示で測ると「答えを知っていた」可能性がある(DECISIONS D05)。そのため、**評価セットは精度の目安**とし、最終的には運用開始後の `value_candidate`・`value_catalyst` の記録で測る。

## 9. 過去検証(`backtest.py`)

「有名投資家の手法だから勝てる」とは仮定しない。**生き残ったのは勝った人だけ**で、共通点が勝因とは限らない(`INVESTOR_RESEARCH.md` §2.3)。

| 偏り | 防ぎ方 | テスト |
|---|---|---|
| 先読み | 財務は開示日 < 基準日のものだけ。当日の開示も使わない。株価も基準日以前だけで Snapshot を作る。作ったあとにも assert で検査 | `test_lookahead_trap_*` |
| 生存者バイアス | マスタに上場廃止銘柄が無ければ警告(`--require-delisted` でエラー)。株価が途切れた観測は最後の終値で評価して**数える**(捨てない) | `test_survivorship_*`、`test_delisted_*` |
| 約定できない価格 | 売買代金の下限を満たす銘柄だけ。ベースラインにも同じ足切りを適用 | `test_illiquid_*` |
| 比較対象の取り違え | ベースライン=同じ日・同じ足切り・同じ危険信号の除外を通った全銘柄 | |
| 同日の観測は独立でない・地合いに該当が偏る | 基準日数を併記。p値は**日付ごとに層別**した並べ替え検定(その日のベースラインから、その日の該当数だけ抽出)。層別しないと、型B・Dで偽陽性が57〜95%(`VALUE_VALIDATION.md` §2.1) | `test_stratified_permutation_*` |
| 測る期間が型に合わない | 20・60・120・250営業日の超過リターンを、日付ごとの差(t値)で比べる(`horizon_table`)。A・Bは長い期間で見る | `test_horizon_table_verdicts` |
| 効果の取り逃し・偽陽性 | 「効果を仕込んだ世界」で検出でき、「効果のない世界」では勝ちと言わないことをテストで確認 | `test_detects_planted_effect_*`、`test_no_effect_world_*` |

- 監理・継続企業の疑義は**現在の状態**で過去には使えないため、検証では使わない(その分、実運用より危険銘柄が混じる)。
- 検証の基準日は月末の最終営業日。上場廃止の「清算値」は取れないので、最後の終値で評価する(楽観側に偏る。警告に出す)。
- 結果は「ベースラインより高い(要・別期間での再確認)」と出ても、**`VALUE_VALIDATION.md` §5 の主セルで、前半・後半の両期間の確認を通るまで採用しない**。

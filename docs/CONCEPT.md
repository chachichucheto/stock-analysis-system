## 0. なぜこの文書を作ったか

`DESIGN.md` は v0.1 → v0.3 と、議論のたびに機能を**足し算**してきた。その結果、次の問題が出ている。

1. **目的が3つ混ざっている**
   - 自分の売買に使う道具
   - 連想に優位性があるかを証明する研究
   - 自動の予測器

   ChatGPT案は研究の側に強く寄っている。一方、本来の目的は道具である。
2. **優位性の源泉が書かれていない**:なぜこのやり方で市場に勝てるのかが明文化されていない。
3. **中心となる単位が曖昧**:イベント・仮説・候補の3つが並立していて、どれを軸に回すのかがはっきりしない。
4. **核心が未検証のまま周辺が膨らんだ**:「連想で選んだ銘柄は上がるのか」が分からないうちに、問いが20個、関門が2つ、対照群が4種類と増えた。

この文書は、**変えてはいけない大枠**だけを1枚にまとめたものである。

## 1. 一言でいうと

> **大きなニュースから生まれる「連想シナリオ」を毎日少数だけ立て、個人投資家に広がる前に候補銘柄を示す。その結果をすべて記録し、連想が本当に効くかを確かめながら改善し続ける道具。**

- 主目的は**道具**(あなたの売買判断を助ける)。
- 検証は道具に**組み込まれた答え合わせ**として行う。研究基盤を先に作ることはしない。
- 自動の予測器にはしない。最終判断は常にあなたが行う。

### 1.1 道具の出力(= ゴールの定義)

> **毎晩30分以内に、翌営業日以降の売買判断に使える本命(0〜3銘柄)が、根拠と「崩れる条件」付きで手元に届く。そして月に1回、それが本当に効いているかが数字で分かる。**

出力は次の3つだけとする。

| # | 出力 | 頻度 | 用途 |
|---|---|---|---|
| **O1** | **連想レポート** | 毎晩 | 翌日以降の売買判断(主な出力) |
| **O2** | **答え合わせレポート** | 月1回(週1回は簡易版) | 道具が効いているかの判定。§7 の L1・L2 の判定に使う |
| **O3** | 連携ファイル(CSV) | 毎晩 | 需給・ファンダのシステムに本命を渡す(S4 以降) |

#### O1 連想レポートの構成

```
━━ 連想レポート 2026-10-01(水)夜 ━━━━━━━━━━━━━━━━━━
■ 今日の結論:本命 2銘柄 / 新しいシナリオ 1件 / 強化 1件 / 終了 1件

■ 自信度ランキング(進行中の全シナリオから。上位ほど自信あり)
 順位 銘柄          自信度 実現確度 残り余地  鮮度  織り込み 診断
 1位 銘柄A(xxxx)   ★★★★  70%   +35%   85%   15%   時間差あり
 2位 銘柄B(xxxx)   ★★★   55%   +30%  100%    0%   未発見
 ─── ここまで本命 ───────────────────────────
 3位 銘柄C(xxxx)   ★★    60%   +10%   60%   65%   織り込み進行
 4位 銘柄D(xxxx)   ★     40%   +25%   40%    0%   ⚠ 無視されている疑い

■ 本命1位 銘柄A(xxxx)  時価総額 xxx億円 / 売買代金 xx億円
│ シナリオ :「〇〇が起きた → △△が不足する → □□を作る会社が買われる」(#15・段階2)
│ 連想の道筋:ニュース → 1段目(大手、すでに+15%) → 2段目(この銘柄、+3%)
│ 材料の強さ:想定上昇幅 +20〜60%(中央 +40%)
│            根拠:影響額が時価総額の8%/類似事例3件の上昇幅/小型
│ 鮮度      :85%(初報から2営業日、昨日の強化で一部回復)
│ 織り込み度:15%(ニュース前からの超過上昇 +6% ÷ 想定上昇幅 +40%)
│ 反応の診断:時間差あり ― 1段目は反応済み、この銘柄はまだ。出来高は増え始め
│ 実現確度 :70%(シナリオの強さ Medium/方向は明確/裏取り 3/4 確認済み)
│ 裏取り   :① 〇〇の不足 ― ✓ 統計で確認(〇月の出荷 −30%、URL)
│            ② 価格の上昇 ― ✓ 店頭価格 +12%(前年比、URL)
│            ③ この会社の売上比率 ― ✓ 有報で□□事業が4割(URL)
│            ④ 会社の受注増 ― 未確認(次の確認:〇月〇日の月次売上)
│ 反証の調査:在庫・輸入で補える量は限定的(URL)
│ 時間の型 :単発型・想定期間10営業日(起動済み・残り8営業日)
│ 背景テーマ:半導体(温度 高・上昇中 → 追い風)
│ 反論     :大手が内製に切り替えれば恩恵が消える
│ 崩れる条件:〇〇の報道が収束する/会社が関与を否定する
│            /10営業日たっても出来高が増えない
│ 次の材料 :〇月〇日の政府発表で予算が付けば、シナリオが強化される
└ あなたの判断:[ 買う / 監視 / 見送り ] 理由:____

■ シナリオの変化
  ・#12「アクティビスト介入」 段階2→3に強化(株主提案の報道)
  ・#08「〇〇特需」 終了:材料が弱かった(注目度はピーク済み、12営業日、1段目も含めて反応なし)

■ 保有株への警戒:なし
```

- **本命がない日は「該当なし」とだけ出す。** 無理に候補を出さない。
- 各本命には、**崩れる条件と次の材料を必ず付ける。** 買ったあとに何を見ていればよいかが分かるようにするためである。
- ランキングの対象は**その日のニュースだけでなく、進行中の全シナリオ**とする。数日前に立てて昨日強化されたシナリオが、1位になることもある。

#### O2 答え合わせレポートの構成

1. **結論**:本命は単純な方法に勝っているか(コスト控除後、ストップ高で買えなかった分も考慮)
2. シナリオの型別の成績(どの型の連想が効いているか)
3. あなたの判断の成績(買った本命と見送った本命の比較)
4. 運用の状況(実行した日数、平均の作業時間)
5. 次の改善の候補(§9.1 の追加条件に当たったもの)

### 1.2 3つの物差し:鮮度・材料の強さ・織り込み度

候補を判断する物差しとして、次の3つを使う。

| 物差し | 意味 | 求め方 |
|---|---|---|
| **鮮度** | 材料がまだ新しいか | シナリオの**起動日**(単発型は初報の日)を100%とし、そのシナリオの想定期間に対する経過の割合で減らす。**待機中は減らさない。新しい事実で強化されたら回復させる** |
| **材料の強さ(想定上昇幅)** | この材料で最終的にどこまで上がり得るか | LLMが幅で推定する(例:+20〜60%)。根拠は次の4つ。①ニュースの等級(§1.4。S級ほど大きい) ②影響額と時価総額の比 ③過去の類似事例の上昇幅 ④時価総額の小ささ・テーマの寿命 |
| **織り込み度** | 想定上昇幅のうち、どこまで株価が動いたか | **ニュース前日からのTOPIX超過の上昇 ÷ 想定上昇幅** |

#### 織り込み度は「上がった量」ではなく「上がり得る量との比」で見る

- ストップ高まで上がっても、材料が強烈で最終的に3倍になり得るなら、織り込み度はまだ5%程度である。
- 逆に、+5%しか上がっていなくても、材料が小さければ織り込み度は100%近い。
- つまり、**織り込み度の分母である「材料の強さ」をどう見積もるかが核心**になる。この見積もりはニュース初日には確定しないので、推定値として記録する。O2 で「強いと見積もった材料は、本当に大きく上がったか」を答え合わせし、見積もり方を改善していく。

#### 「全く反応しない」の見分け方:未発見か、材料が弱いか

ご指摘のとおり、反応がないまま時間がたつなら、それは材料が弱かった可能性が高い。**市場が反応しないこと自体が、材料の強さについての情報**である。そこで、反応がない状態を次の2つの物差しで見分ける。

**物差し1:注目度(ニュースがどれだけ知られているか)**

| | 株価が反応した | 株価が反応しない |
|---|---|---|
| **注目度が高い**(広く知られている) | 織り込み進行中 → 残り余地を見る | **⚠ 無視されている** → 市場は弱い材料と判断した疑い。確度を大きく下げる |
| **注目度が低い**(まだ知られていない) | 早耳筋が先回り → 追随するか要判断 | **未発見** → 狙い目の候補。ただし広がるきっかけ(次の材料)が必要 |

**物差し2:1段目の銘柄の反応(本モデルの優位性①に直結)**

| 1段目の銘柄 | 2段目(候補)の銘柄 | 診断 |
|---|---|---|
| 反応した | まだ反応していない | **時間差あり** ― 最も狙いたい状態 |
| 反応した | 反応した | 織り込み進行 → 残り余地を見る |
| 反応していない | 反応していない | **材料そのものが弱い疑い** |

#### 賞味期限:日数で一律に決めず、シナリオごとに「型」と「条件」で決める

ニュースの賞味期限は事例によって大きく違う。単発の提携発表は数日で終わるが、大地震の復興需要は、パニックが収まるまで始まらない。そこで、賞味期限は次のように扱う。

**1. シナリオを立てるときに「時間の型」を決め、記録する**

| 時間の型 | 例 | 時計の動き方 |
|---|---|---|
| **単発型** | 提携・受注・不祥事・大量保有報告書 | 初報から時計が動く。短い(目安5〜10営業日) |
| **局面展開型** | 大地震・パンデミック・戦争・政変 | **局面ごとに時計を持つ。** 次の局面の「起動条件」を満たすまで、その局面のシナリオは**待機**(時計は止まったまま) |
| **予定日型** | 選挙・政策の施行日・大型催事 | 予定日に向けて動き、予定日の数日後に終わる |

**2. 局面展開型は「いつ」ではなく「何が起きたら」で動かす**

南海トラフ地震の例:

```
局面1 パニック     全面安。防災用品・代替生産などの即時シナリオだけが進行中
  │  起動条件:市場の下げ止まり(例:TOPIXが3日続伸)、または政府の復興予算の報道
  ▼
局面2 冷静化       「復興需要」シナリオが待機 → 進行中へ。ここから時計が動く
  │  起動条件:補正予算の成立・発注の開始
  ▼
局面3 実需         受注・業績の上方修正の段階。シナリオの強化として扱う
```

- 「復興需要」シナリオは、地震の当日に**待機状態で立てておく**。10日後に起動するか20日後に起動するかは、日数ではなく起動条件で決まる。
- 起動条件と終了条件は、シナリオを立てるときにLLMが提案し、その日のうちに確定・記録する。後から都合よく変えない。

**3. 「材料が弱かった」の判定は、そのシナリオ自身の時計で行う**

| 条件 | 判定 |
|---|---|
| **起動後**、そのシナリオの想定期間を過ぎても1段目・2段目とも反応しない(注目度はピーク済み) | 終了:**材料が弱かった** |
| 起動後、1段目は反応したのに、想定期間の2倍を過ぎても2段目が反応しない | 終了:**連想が市場に届かなかった** |
| 織り込み度が80%以上 | 終了:**織り込み完了** |
| 終了条件に当たった | 終了:**シナリオ崩壊** |
| 起動条件を満たさないまま60営業日たった | 終了:**起動せず**(スイングの対象外とする) |

**4. 期限の目安は記録から学ぶ**

最初の想定期間はLLMの推定にすぎない。O2 で「時間の型ごとに、起動から反応までに実際に何日かかったか」を集計し、目安を実データで置き換えていく。

- 終了したシナリオも記録として残し、「どの型の材料が弱かったか」「どの型の連想が届かなかったか」の集計に使う。

### 1.3 自信度ランキング

**上位ほど自信がある順**に並べる。考え方は「当たる確率 × 当たったときの残りの取り分」、つまり期待値である。

```
自信度 = 実現確度 × 残り余地 × 鮮度の補正

  実現確度 = シナリオが実現して株価が動く確率(LLMが推定)
             ・シナリオの強さの段階(Weak〜Strong)
             ・裏取りの進み具合(連想の矢印のうち、事実で確認できた割合。§1.6)
             ・反証の調査の結果(打ち消す事実が見つかれば下げる)
             ・方向の明確さ(プラスにもマイナスにも読めるものは下げる)
             ・反応の診断(「無視されている」は大きく下げる)
             ・背景テーマの温度(追い風なら上げ、逆風なら下げる)
  残り余地 = 想定上昇幅 × (1 − 織り込み度)
  鮮度の補正 = 古い材料ほど下げる
```

- 上位3件までを本命、それ以下を監視とする。流動性の下限を満たさない銘柄は本命にしない。
- ★の数は、自信度を過去の分布の中での位置(上位何%か)で表示する。
- **ランキング自体も答え合わせする。** O2 で「1位の銘柄の成績は3位より良いか」「実現確度70%と言った候補は、実際に7割当たっているか」を確かめる。確度の数字が当たっていなければ、LLMが自信過剰か過小かが分かるので、推定の仕方を補正する。
- 計算式の重みは暫定である。初日は単純な掛け算で始め、記録がたまってから見直す。

### 1.4 反応すべきニュースの見分け方(粒度の核心)

#### 原則:鮮度はテーマではなく「事実」に付く

AI や防衛というテーマそのものは古く、鮮度は低い。しかし「TSMCが来年の発注を100倍にする」という**事実**は新しく、しかも市場の想定を桁違いに超える。株価を動かすのはテーマの新しさではなく、**市場の想定からのズレ(サプライズ)**である。

したがって、反応すべきかどうかは、テーマが新しいか古いかでは決めない。**そのニュースが、市場が今織り込んでいる前提をどれだけ裏切るか**で決める。

#### テーマの前提カード:サプライズを測る基準線

サプライズを判定するには、「市場は今何を想定しているか」という基準が要る。そこで、テーマごとに**前提カード**を持つ。

```
テーマ:AI・データセンター   前提カード v7(2026-09-20 更新)
 ・市場の前提:大手のデータセンター投資は年 +30% 程度の成長が続く
 ・注目の数字:大手クラウド4社の設備投資額、TSMCの先端品の生産能力
 ・前提を崩す方向:投資の急減速、規制、電力不足
 ・温度:高・上昇中
```

- 前提カードは LLM が作り、**S級・A級のニュース(下記)が出たときだけ更新する**。版管理し、どの版を基準に判定したかを記録する。
- 新しいニュースは、この前提と比べて判定する。これで、判定の基準が毎日ぶれない。

#### ニュースの4つの等級

| 等級 | 意味 | 例 | 扱い |
|---|---|---|---|
| **S スーパーサプライズ** | 前提そのものが変わる。数字の桁が変わる、制度や前提条件が変わる。**または、まだ存在しないテーマが生まれる(§1.5)** | TSMCが発注を100倍に/大型の規制撤廃/大地震/新しい技術・現象の登場 | **必ず処理する。** テーマが古くても、新しいシナリオを鮮度100%で立てる。前提カードを更新する |
| **A サプライズ** | 前提の範囲を明確に超える | 想定を大きく超える受注・予算額・上方修正 | 処理する。新しいシナリオを立てるか、既存のシナリオを強化する |
| **B 想定内の進展** | 前提の範囲内で、既知の流れが続いている | 予想どおりの決算、計画どおりの工場稼働 | **シナリオは立てない。** テーマの温度を更新するだけ |
| **C ノイズ** | 新しい事実がない | 論評、繰り返し報道、観測記事の再掲 | 記録するだけ |

#### 等級を決める4つの質問

| # | 質問 | 判定する担当 |
|---|---|---|
| 1 | **新しい事実か** ― 過去の報道や観測記事に同じ内容がないか | Python(蓄積したニュースを検索)+ LLM |
| 2 | **前提からどれだけ離れているか** ― 前回の数字・会社計画・観測値と比べて何倍か。方向は逆転しているか | LLM(前提カードと比較。数字を必ず並べて示す) |
| 3 | **誰が、どれだけ確定的に言ったか** ― 公式発表か、観測・噂か。当事者は業界の中心企業・政府か | LLM |
| 4 | **市場は実際に驚いたか** ― 1段目の銘柄(海外の当事者企業を含む)の当日の値動きが、普段の値動きの何倍か | **Python(客観的な検算)** |

- 質問1〜3 は LLM の判断、質問4 は市場の実際の反応による**検算**である。LLM が S級と判定しても、1段目の銘柄が全く動かなければ、等級を下げる。逆に LLM が B級と判定しても、1段目の銘柄が普段の数倍動いていれば、見落としとして再判定する。
- 米国企業の発表なら、日本の寄り付き前に米国市場での反応が分かる。日本の2段目の銘柄を狙う本モデルにとって、これは有利な時間差になる。

#### テーマの温度とサプライズの関係

- **熱いテーマの良いニュース**は、想定内(B級)になりやすい。市場がすでに期待しているためである。
- **冷えたテーマの良いニュース**や、**熱いテーマの悪いニュース**は、同じ大きさでもサプライズ(A・S級)になりやすい。
- この関係は前提カードに織り込まれるので、特別な処理は要らない。ただし O2 で「温度別の等級の成績」を確かめる。

#### 答え合わせ

等級も推定であり、O2 で次を確かめる。

- S級は、A級・B級より本当に大きく動いたか
- B級(シナリオを立てなかったもの)の中に、大きく動いたものがなかったか(見逃しの確認)
- 質問4 の検算で等級を修正したケースは、修正が正しかったか

### 1.5 新しいテーマの誕生:最大のサプライズ

**テーマが生まれた瞬間が、最も熱い。** 既存のテーマには前提カードがあり、市場はすでに何かを想定している。新しいテーマには前提そのものが存在しない。市場はまだ何も織り込んでおらず、関連銘柄の一覧すら出回っていない。このため、テーマの誕生はそれ自体が S級のサプライズとして扱う。

#### テーマの一生

温度だけでは足りないので、テーマには**段階**も持たせる。

```
誕生 → 拡散 → 主流 → 成熟 → 冷却
 │      │      │      │
 │      │      │      └ 良いニュースも想定内。B級が中心
 │      │      └ 関連銘柄の一覧が出回り、大型株まで買われる
 │      └ テーマ名が定着し、まとめ記事やランキングに載り始める
 └ まだテーマ名がない。前提カードもない ← 最も狙いたい段階
```

- 例:ChatGPT の公開直後の「生成AI」、光電融合、ステーブルコイン、フィジカルAI などは、どれもかつては誕生の段階にあった。
- **誕生・拡散の段階のテーマに属するシナリオは、実現確度と想定上昇幅を上乗せする。** 成熟・冷却の段階では、同じ大きさのニュースでも差し引く。

#### 誕生の見つけ方(4つの兆候)

| # | 兆候 | 判定する担当 |
|---|---|---|
| 1 | **既存テーマに当てはまらない**:S・A級のニュースが、テーマ一覧(`THEMES.md`)のどれにも属さない | LLM |
| 2 | **新しい言葉の急増**:それまでほぼ使われていなかった言葉が、報道や検索で急に増える(ゼロに近い状態からの立ち上がり) | Python(GDELT・Google News・Wikipedia) |
| 3 | **説明のつかない連れ高**:業種の違う複数の銘柄が同時に上がっており、既存のテーマでは説明できない | Python(株価の連動を検出) |
| 4 | **テーマ名の出現**:株探などの人気テーマに未登録の名前が現れる | 人(週1回確認) |

- 兆候が2つ以上そろったら、テーマを**仮登録**する。段階は「誕生」、前提カードは「市場の前提:まだない」とし、関連シナリオを鮮度100%で立てる。
- **多くの新テーマは定着せずに消える**(一過性のブーム)。仮登録したテーマのうち、どれだけが拡散・主流まで育ったかを O2 で記録する。誕生の段階での見極めの精度を上げるためである。

### 1.6 裏取り調査:連想の矢印を事実で確かめる

**自信を高めるのは、連想そのものではなく、連想の各段階を事実で確かめる調査である。** 連想は仮説にすぎない。矢印の1本1本を観測できるデータで確かめるほど、実現確度は上がる。

#### 確認計画:シナリオを立てるときに、何を見れば確かめられるかを決める

例:「猛暑 → 不作 → 米価の上昇 → 関連銘柄が買われる」

| 矢印 | 確かめる指標 | 情報源の例(無料) | 確認できたと言える基準 | 次の公表 |
|---|---|---|---|---|
| 猛暑が続くか | 気温の実績と予報 | 気象庁の過去の気象データ、1か月・3か月予報 | 主産地で平年より高い予報が続く | 毎週木曜(1か月予報) |
| 不作になるか | 作柄・作況 | 農林水産省の作柄の公表、産地の報道 | 主産地で「やや不良」以下 | 公表日程に従う |
| 米価が上がるか | 販売価格 | 農林水産省の相対取引価格、スーパーの店頭価格の調査 | 前年比で明確に上昇 | 公表日程に従う |
| 会社に効くか | 業績への影響 | 有価証券報告書、月次売上(TDnet) | 関連事業の売上比率が大きい/月次売上が増加 | 月次売上の公表日 |

- 確認計画は、シナリオを立てるときに LLM が提案し、**その日のうちに記録する**。後から作ると、結果を知ったうえで都合の良い指標を選べてしまうためである。
- 矢印ごとに「確認済み ✓/否定 ✗/未確認」を持たせ、レポートに表示する。
- **反証の調査も必ず行う**。例:在庫が十分にある、輸入で補える、政府の備蓄米の放出がある。打ち消す事実が見つかれば、実現確度を下げる。
- 「次の公表」の日付は、シナリオの「次の材料」の欄にもなる。統計が確認されればシナリオの強化(§4)、否定されれば弱体化として扱う。

#### 調査の深さは順位に合わせる(作業時間を守るため)

| 対象 | 調査の深さ |
|---|---|
| ランキング上位(本命の候補) | 確認計画のすべての矢印を、その夜の Claude Code のセッションで調べる(Web検索・公的統計) |
| それ以下 | 確認計画を記録するだけ。調査は、順位が上がったときに行う |

#### 調査結果の扱い

- 証拠として記録するのは、**URL・取得時刻・値**がそろったものだけとする。LLM の推論は証拠にしない。
- 公的統計は**公表日時**も記録する。公表前の数値を使ったことにしないためである。
- 繰り返し使う指標(気温・米価・電力需給・為替・商品価格など)は、**指標ライブラリ**に登録する。2回目以降は、同じ情報源を探し直さずに済む。ライブラリの指標のうち、機械的に取れるものは Python で自動取得に切り替える(§9.1 の追加条件に従う)。

## 2. 優位性の源泉(なぜ勝てるのか)

個人投資家が、スピードでプロに勝つことはできない。本モデルが狙う優位性は、次の3つに限る。

| 源泉 | 中身 |
|---|---|
| **① 拡散の時間差** | 大ニュースの**直接の関連銘柄**は、数分〜1日で織り込まれる。一方、**2段目の連想**が個人投資家に広がるまでには数日〜数週間かかる。スイングで取るのはこの時間差である |
| **② 連想の網羅性** | 人間は、思いついた1〜2個の連想先しか調べられない。LLMは経済的なつながりと投資家の連想の両方を、短時間で広く洗い出せる |
| **③ 規律と記録** | 人間は当たった連想だけを覚えていて、外れを忘れる。全シナリオを記録して答え合わせすれば、**どの型の連想が本当に効くか**を自分のデータで知ることができる |

**狙わないもの**:ニュースへの即時の反応(速さの勝負)、大型株(機関投資家の領域)、経済分析の正しさそのもの(市場が乗らなければ儲からない)。

**この源泉が成り立たない場合**(直接の関連銘柄と同時に2段目の銘柄も織り込まれる、あるいは単純な方法と成績が変わらない場合)、本モデルは中止する(§7)。

## 4. 中心となる単位:連想シナリオ

**すべてを「連想シナリオ」(以下、シナリオ)を中心に回す。**

```
            テーマ(背景・期限なし)  例:AI、半導体、防衛、インバウンド
               │  温度(上昇中/高止まり/冷却中)だけを持つ
               ▼
ニュース(入力) ──→ シナリオ(中心・期限あり) ──→ 候補銘柄(出力)
                    「Xが起きた → だからYが買われる」
                    ・時間の型(単発/局面展開/予定日)と起動・終了条件
                    ・強さ(段階的に強化/弱体化)
                    ・注目度(ニュースの大きさ)
                    ・状態(待機/進行中/休眠/終了)
```

#### テーマとシナリオを分ける(長期の巨大テーマの扱い)

AI や半導体のように、何年も続き、良いニュースも悪いニュースも出続けるものは、**シナリオではなく「テーマ」として別に扱う。** テーマをシナリオとして扱うと、終わりがなく、答え合わせもできないためである。

- **テーマ**:期限を持たない背景。持つのは**温度**と**段階**(誕生・拡散・主流・成熟・冷却。§1.5)だけとする。温度は、テーマ語の注目度(Wikipedia・GDELT)と、テーマ銘柄群の相対的な値動きから Python が計算する。
- **シナリオ**:テーマの中で起きた**個別の具体的な出来事**から立てる、期限のある連想。例:「米国が対中輸出規制を強化 → 国内の製造装置の代替需要」。
- テーマに関するニュースの多くは、**温度を更新するだけで、シナリオは立てない。** 新しいシナリオを立てるのは、関門を通る大きさの新しい事実があるときだけとする。これで、巨大テーマのニュースに振り回されずに済む。
- テーマの温度は、そのテーマに属するシナリオの**追い風・逆風**として、実現確度の補正に使う。

- **ニュース**は、シナリオを**生む**、**強める**、**弱める**、**終わらせる**材料にすぎない。
- **候補銘柄**は、必ずどれか1つのシナリオに属する。シナリオに属さない候補は作らない。
- **評価もシナリオ単位**で行う。1つのシナリオから出た複数の候補は、値動きが連動するので独立に数えない。
- 段階的な強化(不祥事 → スポンサー離れ → 株主提案 → 大量保有報告書)は、特別な機能ではなく**シナリオの自然な一生**として扱う。

これで、v0.3 のイベント・仮説・候補の3つの並立が1本にまとまる。

## 9. 作る順番の原則:後から足せないものだけを最初に作る

v0.3 の反省をふまえ、機能は2つに分ける。

**初日から必須(後から取り戻せない)**

| 項目 | 理由 |
|---|---|
| ニュース・TDnet・上場銘柄一覧の収集 | 無料データは過去分が消える |
| 時刻の記録(いつ知り得たか) | 後から正確に復元できない |
| シナリオと候補の追記専用の記録(落とした候補を含む) | 後から作ると、結果を見た後付けになる |
| 買いの起点のルール(翌営業日の始値、ストップ高で買えなかったものは除外) | 後から変えると、過去の成績と比べられない |
| 比較用の単純な方法の記録(2種類だけ) | 同じ日の記録がないと比較できない |
| 確認計画と裏取りの結果の記録(URL・取得時刻・値) | 後から作ると、結果を見て都合の良い指標を選べてしまう |

**それ以外は、原則として作らない。**

`DESIGN.md` v0.3 の機能の多くはこちらに当たる。これらは開発予定ではなく、**「問題が起きたときの対処法の引き出し」**として残す。次の §9.1 の追加条件に当たったときだけ作る。一度も作らずに終わるものがあっても構わない。

### 9.1 後で足す機能と、その追加条件

| 機能 | 作るのはこういうとき | 作らずに済む代替 |
|---|---|---|
| 格付けの細かい条件 | 本命が1日3件を超える日が続き、選びきれない | 本命の上限を下げる |
| テーマ純度 | 答え合わせで、大型株の本命ばかり負けている | 時価総額の上限を設ける |
| 地合いの特徴量 | 月によって成績の差が極端に大きい | O2 で地合いの良い月・悪い月を目で見て比べる |
| 出口の模擬比較 | 「いつ売るか」で迷うことが多い | 本命カードの「崩れる条件」で判断する |
| 関門の漏れの検査 | 見逃した大相場があとから何度も見つかる | 気づいたときに手動で記録する |
| 出力のばらつきの測定 | 同じ状況で候補が毎回大きく変わる気がする | ― |
| 対照群の追加 | L2 の判定が際どく、比較対象を増やさないと結論が出ない | 単純な方法2種類との比較のみ |
| 事例集 | シナリオの質が低く、プロンプトに型の例が要る | ― |
| 指標の自動取得 | 同じ指標を手作業で3回以上調べた | その都度 Claude Code で調べる |
| 説明のつかない連れ高の自動検出 | 新テーマの誕生を後から知ることが続く | 人が週1回、人気テーマを確認する |
| 既存システムとの連携 | 本命を需給・ファンダで確認する手間が大きい | O3 のCSVを手で開いて見る |

**分析だけで済むものはシステムにしない。** たとえば「地合いによる成績の差」は、記録さえあれば、必要になったときに Claude Code でその場で集計できる。定期的に使うと分かったものだけを機能にする。

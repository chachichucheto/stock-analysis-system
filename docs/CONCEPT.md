## 0. なぜこの文書を作ったか

`DESIGN.md` は v0.1 → v0.3 と、議論のたびに機能を**足し算**してきた。その結果、次の問題が出ている。

1. **目的が3つ混ざっている**
   - 自分の売買に使う道具
   - 連想に優位性があるかを証明する研究
   - 自動の予測器

   ChatGPT案は研究の側に強く寄っている。一方、本来の目的は道具である。
2. **優位性の源泉が書かれていない**:なぜこのやり方で市場に勝てるのかが明文化されていない。
3. **中心となる単位が曖昧**:イベント・仮説・候補の3つが並立していて、どれを軸に回すのかがはっきりしない。
4. **核心が未検証のまま周辺が膨らんだ**:「連想で選んだ銘柄は上がるのか」が分からないうちに、問いが20個、関門が2つ、対照群が4種類と増えた。

この文書は、**変えてはいけない大枠**だけを1枚にまとめたものである。

## 1. 一言でいうと

> **大きなニュースから生まれる「連想シナリオ」を毎日少数だけ立て、個人投資家に広がる前に候補銘柄を示す。その結果をすべて記録し、連想が本当に効くかを確かめながら改善し続ける道具。**

- 主目的は**道具**(あなたの売買判断を助ける)。
- 検証は道具に**組み込まれた答え合わせ**として行う。研究基盤を先に作ることはしない。
- 自動の予測器にはしない。最終判断は常にあなたが行う。

### 1.1 道具の出力(= ゴールの定義)

> **毎晩30分以内に、翌営業日以降の売買判断に使える本命(0〜3銘柄)が、根拠と「崩れる条件」付きで手元に届く。そして月に1回、それが本当に効いているかが数字で分かる。**

出力は次の3つだけとする。

| # | 出力 | 頻度 | 用途 |
|---|---|---|---|
| **O1** | **連想レポート** | 毎晩 | 翌日以降の売買判断(主な出力) |
| **O2** | **答え合わせレポート** | 月1回(週1回は簡易版) | 道具が効いているかの判定。§7 の L1・L2 の判定に使う |
| **O3** | 連携ファイル(CSV) | 毎晩 | 需給・ファンダのシステムに本命を渡す(S4 以降) |

#### O1 連想レポートの構成

```
━━ 連想レポート 2026-10-01(水)夜 ━━━━━━━━━━━━━━━━━━
■ 今日の結論:本命 2銘柄 / 新しいシナリオ 1件 / 強化 1件 / 終了 1件

■ 自信度ランキング(進行中の全シナリオから。上位ほど自信あり)
 順位 銘柄          自信度 実現確度 残り余地  鮮度  織り込み 診断
 1位 銘柄A(xxxx)   ★★★★  70%   +35%   85%   15%   時間差あり
 2位 銘柄B(xxxx)   ★★★   55%   +30%  100%    0%   未発見
 ─── ここまで本命 ───────────────────────────
 3位 銘柄C(xxxx)   ★★    60%   +10%   60%   65%   織り込み進行
 4位 銘柄D(xxxx)   ★     40%   +25%   40%    0%   ⚠ 無視されている疑い

■ 本命1位 銘柄A(xxxx)  時価総額 xxx億円 / 売買代金 xx億円
│ シナリオ :「〇〇が起きた → △△が不足する → □□を作る会社が買われる」(#15・段階2)
│ 連想の道筋:ニュース → 1段目(大手、すでに+15%) → 2段目(この銘柄、+3%)
│ 材料の強さ:想定上昇幅 +20〜60%(中央 +40%)
│            根拠:影響額が時価総額の8%/類似事例3件の上昇幅/小型
│ 鮮度      :85%(初報から2営業日、昨日の強化で一部回復)
│ 織り込み度:15%(ニュース前からの超過上昇 +6% ÷ 想定上昇幅 +40%)
│ 反応の診断:時間差あり ― 1段目は反応済み、この銘柄はまだ。出来高は増え始め
│ 実現確度 :70%(シナリオの強さ Medium/方向は明確/有報で裏付けあり)
│ 反論     :大手が内製に切り替えれば恩恵が消える
│ 崩れる条件:〇〇の報道が収束する/会社が関与を否定する
│            /10営業日たっても出来高が増えない
│ 次の材料 :〇月〇日の政府発表で予算が付けば、シナリオが強化される
└ あなたの判断:[ 買う / 監視 / 見送り ] 理由:____

■ シナリオの変化
  ・#12「アクティビスト介入」 段階2→3に強化(株主提案の報道)
  ・#08「〇〇特需」 終了:材料が弱かった(注目度はピーク済み、12営業日、1段目も含めて反応なし)

■ 保有株への警戒:なし
```

- **本命がない日は「該当なし」とだけ出す。** 無理に候補を出さない。
- 各本命には、**崩れる条件と次の材料を必ず付ける。** 買ったあとに何を見ていればよいかが分かるようにするためである。
- ランキングの対象は**その日のニュースだけでなく、進行中の全シナリオ**とする。数日前に立てて昨日強化されたシナリオが、1位になることもある。

### 1.2 3つの物差し:鮮度・材料の強さ・織り込み度

候補を判断する物差しとして、次の3つを使う。

| 物差し | 意味 | 求め方 |
|---|---|---|
| **鮮度** | 材料がまだ新しいか | 初報の日を100%とし、営業日の経過とともに減らす(暫定:半減期5営業日)。**新しい事実で強化されたら回復させる** |
| **材料の強さ(想定上昇幅)** | この材料で最終的にどこまで上がり得るか | LLMが幅で推定する(例:+20〜60%)。根拠は次の3つ。①影響額と時価総額の比 ②過去の類似事例の上昇幅 ③時価総額の小ささ・テーマの寿命 |
| **織り込み度** | 想定上昇幅のうち、どこまで株価が動いたか | **ニュース前日からのTOPIX超過の上昇 ÷ 想定上昇幅** |

#### 織り込み度は「上がった量」ではなく「上がり得る量との比」で見る

- ストップ高まで上がっても、材料が強烈で最終的に3倍になり得るなら、織り込み度はまだ5%程度である。
- 逆に、+5%しか上がっていなくても、材料が小さければ織り込み度は100%近い。
- つまり、**織り込み度の分母である「材料の強さ」をどう見積もるかが核心**になる。この見積もりはニュース初日には確定しないので、推定値として記録する。O2 で「強いと見積もった材料は、本当に大きく上がったか」を答え合わせし、見積もり方を改善していく。

#### 「全く反応しない」の見分け方:未発見か、材料が弱いか

ご指摘のとおり、反応がないまま時間がたつなら、それは材料が弱かった可能性が高い。**市場が反応しないこと自体が、材料の強さについての情報**である。そこで、反応がない状態を次の2つの物差しで見分ける。

**物差し1:注目度(ニュースがどれだけ知られているか)**

| | 株価が反応した | 株価が反応しない |
|---|---|---|
| **注目度が高い**(広く知られている) | 織り込み進行中 → 残り余地を見る | **⚠ 無視されている** → 市場は弱い材料と判断した疑い。確度を大きく下げる |
| **注目度が低い**(まだ知られていない) | 早耳筋が先回り → 追随するか要判断 | **未発見** → 狙い目の候補。ただし広がるきっかけ(次の材料)が必要 |

**物差し2:1段目の銘柄の反応(本モデルの優位性①に直結)**

| 1段目の銘柄 | 2段目(候補)の銘柄 | 診断 |
|---|---|---|
| 反応した | まだ反応していない | **時間差あり** ― 最も狙いたい状態 |
| 反応した | 反応した | 織り込み進行 → 残り余地を見る |
| 反応していない | 反応していない | **材料そのものが弱い疑い** |

#### 有効期限:待ち続けない

反応を待つ期間には上限を設け、過ぎたらシナリオを**自動で終了**する(暫定値。O2 で調整する)。

| 条件 | 判定 |
|---|---|
| 注目度がピークを過ぎ、10営業日たっても1段目・2段目とも反応しない | 終了:**材料が弱かった** |
| 1段目は反応したが、20営業日たっても2段目が反応しない | 終了:**連想が市場に届かなかった** |
| 想定上昇幅の大半(織り込み度80%以上)まで上がった | 終了:**織り込み完了** |

- 終了したシナリオも記録として残す。「どの型の材料が弱かったか」「どの型の連想が届かなかったか」は O2 で集計し、材料の強さの見積もりの改善に使う。
- 100日後に上がった場合は、スイングの対象外とする(本モデルの時間差の仮説とは別物のため)。

### 1.3 自信度ランキング

**上位ほど自信がある順**に並べる。考え方は「当たる確率 × 当たったときの残りの取り分」、つまり期待値である。

```
自信度 = 実現確度 × 残り余地 × 鮮度の補正

  実現確度 = シナリオが実現して株価が動く確率(LLMが推定)
             ・シナリオの強さの段階(Weak〜Strong)
             ・一次情報の裏付けの有無
             ・方向の明確さ(プラスにもマイナスにも読めるものは下げる)
             ・反応の診断(「無視されている」は大きく下げる)
  残り余地 = 想定上昇幅 × (1 − 織り込み度)
  鮮度の補正 = 古い材料ほど下げる
```

- 上位3件までを本命、それ以下を監視とする。流動性の下限を満たさない銘柄は本命にしない。
- ★の数は、自信度を過去の分布の中での位置(上位何%か)で表示する。
- **ランキング自体も答え合わせする。** O2 で「1位の銘柄の成績は3位より良いか」「実現確度70%と言った候補は、実際に7割当たっているか」を確かめる。確度の数字が当たっていなければ、LLMが自信過剰か過小かが分かるので、推定の仕方を補正する。
- 計算式の重みは暫定である。初日は単純な掛け算で始め、記録がたまってから見直す。

#### O2 答え合わせレポートの構成

1. **結論**:本命は単純な方法に勝っているか(コスト控除後、ストップ高で買えなかった分も考慮)
2. シナリオの型別の成績(どの型の連想が効いているか)
3. あなたの判断の成績(買った本命と見送った本命の比較)
4. 運用の状況(実行した日数、平均の作業時間)
5. 次の改善の候補(§9.1 の追加条件に当たったもの)

## 2. 優位性の源泉(なぜ勝てるのか)

個人投資家が、スピードでプロに勝つことはできない。本モデルが狙う優位性は、次の3つに限る。

| 源泉 | 中身 |
|---|---|
| **① 拡散の時間差** | 大ニュースの**直接の関連銘柄**は、数分〜1日で織り込まれる。一方、**2段目の連想**が個人投資家に広がるまでには数日〜数週間かかる。スイングで取るのはこの時間差である |
| **② 連想の網羅性** | 人間は、思いついた1〜2個の連想先しか調べられない。LLMは経済的なつながりと投資家の連想の両方を、短時間で広く洗い出せる |
| **③ 規律と記録** | 人間は当たった連想だけを覚えていて、外れを忘れる。全シナリオを記録して答え合わせすれば、**どの型の連想が本当に効くか**を自分のデータで知ることができる |

**狙わないもの**:ニュースへの即時の反応(速さの勝負)、大型株(機関投資家の領域)、経済分析の正しさそのもの(市場が乗らなければ儲からない)。

**この源泉が成り立たない場合**(直接の関連銘柄と同時に2段目の銘柄も織り込まれる、あるいは単純な方法と成績が変わらない場合)、本モデルは中止する(§7)。

## 3. 3つのモデルの関係

| モデル | 答える問い | 役割 |
|---|---|---|
| ファンダメンタルズ | **何を**持つ価値があるか | 価値(乗ってはいけない銘柄の除外) |
| 需給(CIS参考) | **いつ**資金が入るか | タイミング(資金流入の確認) |
| **連想(本モデル)** | **なぜ今**注目されるか | きっかけ・物語(候補の発見) |

本モデルは「なぜ今」だけを担当し、他の2つの役割を自前で作り直さない。連携はファイルの受け渡しだけで行い、既存の2つのシステムは変更しない。

## 4. 中心となる単位:連想シナリオ

**すべてを「連想シナリオ」(以下、シナリオ)を中心に回す。**

```
ニュース(入力) ──→ シナリオ(中心) ──→ 候補銘柄(出力)
                    「Xが起きた → だからYが買われる」
                    ・強さ(段階的に強化/弱体化)
                    ・注目度(ニュースの大きさ)
                    ・状態(進行中/休眠/終了)
```

- **ニュース**は、シナリオを**生む**、**強める**、**弱める**、**終わらせる**材料にすぎない。
- **候補銘柄**は、必ずどれか1つのシナリオに属する。シナリオに属さない候補は作らない。
- **評価もシナリオ単位**で行う。1つのシナリオから出た複数の候補は、値動きが連動するので独立に数えない。
- 段階的な強化(不祥事 → スポンサー離れ → 株主提案 → 大量保有報告書)は、特別な機能ではなく**シナリオの自然な一生**として扱う。

これで、v0.3 のイベント・仮説・候補の3つの並立が1本にまとまる。

## 5. 役割分担

| 担当 | やること | やらないこと |
|---|---|---|
| **Python(自動)** | 収集、注目度の計測、株価の状態の計算、時刻の記録、銘柄の照合、答え合わせ | 解釈、連想 |
| **LLM(Claude Code・手動で1日1回)** | シナリオを立てる・更新する、連想する、反論する | 時刻や数値を決めること、記録の確定 |
| **あなた** | 本命から選ぶ、見送る、理由を一言残す | 毎日全部を読むこと |

**原則:事実と数字は Python、発想は LLM、最終判断はあなた。**

## 6. 毎日の流れ(これ以上増やさない)

```
① 選ぶ    強いニュースだけを残す(Python)             → 0〜3件
② 立てる  シナリオを新しく立てる・更新する(LLM)
③ 絞る    本命の候補を出す(LLM + Python)            → 0〜3銘柄。「該当なし」も正常
④ 記録    すべて追記で確定する(Python)
⑤ 答え合わせ  過去のシナリオの結果を自動で更新する(Python)
```

- あなたの作業時間は**1日15〜30分**を上限とする。超えるなら①の絞り方を見直す。
- 新しい機能は、この5つのどこに属するかを言えなければ追加しない。

## 7. 成功と撤退の基準

| 段階 | 基準 | 判定の時期 |
|---|---|---|
| **L1 運用が成り立つ** | 毎晩の作業が30分以内に収まり、3か月間、ほぼ毎日回る | 運用開始から3か月 |
| **L2 連想が効く** | 本命が、単純な方法(出来高の急増・直接の関連銘柄)を、**コストを引き、ストップ高で買えなかった分も考慮したうえで**上回る | 独立したシナリオが60件たまった時点(目安6か月) |
| **L3 実利がある** | あなたの判断と組み合わせたときに、実際の売買の成績を押し上げる | L2 の後 |

**撤退**:L1 が成り立たなければ、作業を簡略化する。L2 が否定されたら、中止するか方針を転換する。判定の数値は運用開始前に固定し、結果を見てから変えない。

## 8. やること・やらないこと

**やる**:日本株、スイング(数日〜数週間)、上昇側の候補(警戒は注記のみ)、無料データ、候補の提示まで、ローカルでの運用。

**やらない**:
- 自動売買
- デイトレ・即時の反応
- 空売りの推奨
- 海外株
- 有料データ
- 全ニュースの網羅
- **過去データのバックテストで有効性を証明すること**(LLMが過去の結末を知っているため、成り立たない)

## 9. 作る順番の原則:後から足せないものだけを最初に作る

v0.3 の反省をふまえ、機能は2つに分ける。

**初日から必須(後から取り戻せない)**

| 項目 | 理由 |
|---|---|
| ニュース・TDnet・上場銘柄一覧の収集 | 無料データは過去分が消える |
| 時刻の記録(いつ知り得たか) | 後から正確に復元できない |
| シナリオと候補の追記専用の記録(落とした候補を含む) | 後から作ると、結果を見た後付けになる |
| 買いの起点のルール(翌営業日の始値、ストップ高で買えなかったものは除外) | 後から変えると、過去の成績と比べられない |
| 比較用の単純な方法の記録(2種類だけ) | 同じ日の記録がないと比較できない |

**それ以外は、原則として作らない。**

`DESIGN.md` v0.3 の機能の多くはこちらに当たる。これらは開発予定ではなく、**「問題が起きたときの対処法の引き出し」**として残す。次の §9.1 の追加条件に当たったときだけ作る。一度も作らずに終わるものがあっても構わない。

### 9.1 後で足す機能と、その追加条件

| 機能 | 作るのはこういうとき | 作らずに済む代替 |
|---|---|---|
| 格付けの細かい条件 | 本命が1日3件を超える日が続き、選びきれない | 本命の上限を下げる |
| テーマ純度 | 答え合わせで、大型株の本命ばかり負けている | 時価総額の上限を設ける |
| 地合いの特徴量 | 月によって成績の差が極端に大きい | O2 で地合いの良い月・悪い月を目で見て比べる |
| 出口の模擬比較 | 「いつ売るか」で迷うことが多い | 本命カードの「崩れる条件」で判断する |
| 関門の漏れの検査 | 見逃した大相場があとから何度も見つかる | 気づいたときに手動で記録する |
| 出力のばらつきの測定 | 同じ状況で候補が毎回大きく変わる気がする | ― |
| 対照群の追加 | L2 の判定が際どく、比較対象を増やさないと結論が出ない | 単純な方法2種類との比較のみ |
| 事例集 | シナリオの質が低く、プロンプトに型の例が要る | ― |
| 既存システムとの連携 | 本命を需給・ファンダで確認する手間が大きい | O3 のCSVを手で開いて見る |

**分析だけで済むものはシステムにしない。** たとえば「地合いによる成績の差」は、記録さえあれば、必要になったときに Claude Code でその場で集計できる。定期的に使うと分かったものだけを機能にする。

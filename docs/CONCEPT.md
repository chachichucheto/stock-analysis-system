## 1. 目的とゴール

### 1.1 一言でいうと

> **強いニュースが出たその夜に、市場がこれから買いに行く銘柄を、根拠付きで上位に挙げる道具。**

- テスタ氏が得意とする「ニュースからの連想ゲーム」を、個人でも毎日回せる形にする。
- **道具**である。最終判断は常にあなたが行う。自動売買はしない。
- 既存のファンダメンタルズ分析システム、需給分析システム(CIS氏を参考)に続く、3つ目のモデルである。

### 1.2 ゴール(合格の定義)

> **強いニュースを捉えて、有望な銘柄を的確に挙げられれば合格。**

- 本プロジェクトで測るのは**探す能力**である。売買の成績(手数料、ストップ高で買えたか、いつ売るか)は評価の対象にしない。
- 探す能力は、次の3つの指標で測る。

| 指標 | 意味 | 見方 |
|---|---|---|
| **的中率** | 上位に挙げた銘柄のうち、実際に「動いた」割合 | 同じ期間に全銘柄の中から偶然「動いた」銘柄の割合と比べる |
| **捕捉率** | そのニュースで実際に動いた関連銘柄のうち、事前に挙げられていた割合 | 見逃しの裏返し。低ければ、連想の幅が足りない |
| **先行性** | 市場が動き出す前に挙げられていたか | 動き出したあとに挙げても意味は小さい |

- 「動いた」の定義は1つに決めて、運用開始前に固定する(初期値:本命に挙げた日から想定期間内(最長20営業日)に、起点から TOPIX に対して +10% 以上上回った)。
- 数える単位は2つ持つ。日々の確認は**銘柄単位**(本命に挙げた銘柄のうち何割が動いたか)で行い、合否の判定(§11)は**シナリオ単位**(本命のうち1銘柄でも動いたシナリオの割合)で行う。同じシナリオの銘柄は値動きが連動するためである。
- 指標は**改善のために測る**。点数を付けること自体に目的はない(§9.2)。

### 1.3 前提条件

| 項目 | 決定 |
|---|---|
| 対象 | 日本株 |
| 時間軸 | スイング(数日〜数週間) |
| 出力 | 候補の提示まで。売買の判断材料は付けるが、売買の指示はしない |
| データ | 無料のものだけ |
| 株価 | yfinance(ローカルで取得・日次更新している既存データを再利用) |
| LLM | Claude Code を手動で1日1回実行する(APIでの自動化はしない) |
| 実行環境 | 最終的にローカルで運用する。コードと文書は git で受け渡し、データは git に入れない |

## 2. なぜ勝てるのか(優位性の源泉)

個人投資家は、スピードではプロに勝てない。本モデルが狙う優位性は次の3つに限る。

| 源泉 | 中身 |
|---|---|
| **① 拡散の時間差** | 大ニュースの**直接の関連銘柄(1段目)**は、数分〜1日で織り込まれる。一方、**2段目の連想**が個人投資家に広がるまでには数日〜数週間かかる。スイングで狙うのはこの時間差である(中心の仮説) |
| **② 連想の網羅性** | 人間は思いついた1〜2個の連想先しか調べられない。LLM は経済的なつながりと投資家の連想の両方を、短時間で広く洗い出せる |
| **③ 規律と記録** | 人間は当たった連想だけを覚えて、外れと見逃しを忘れる。すべて記録して振り返れば、どの型の連想が効くかが分かる |

**狙わないもの**:ニュースへの即時の反応(速さの勝負)、大型株(機関投資家の領域)、経済分析の正しさそのもの(市場が乗らなければ動かない)。

## 3. 3つのモデルの関係

| モデル | 答える問い | 役割 |
|---|---|---|
| ファンダメンタルズ | **何を**持つ価値があるか | 価値(乗ってはいけない銘柄の除外) |
| 需給(CIS参考) | **いつ**資金が入るか | タイミング(資金流入の確認) |
| **連想(本モデル)** | **なぜ今**注目されるか | きっかけ・物語(候補の発見) |

本モデルは「なぜ今」だけを担当する。連携はファイル(CSV)の受け渡しだけで行い、既存の2つのシステムは変更しない。

## 4. 全体像:テーマ・シナリオ・候補

```
テーマ(背景・期限なし)   例:AI・半導体、防衛、消費税減税、インバウンド
  ・温度(上昇中/横ばい/冷却中)
  ・前提カード(市場が今何を想定しているか)
        │
        ▼
ニュース ──→ シナリオ(中心・期限あり) ──→ 候補銘柄(1シナリオ最大5銘柄)
             「Xが起きた → だからYが買われる」
             ・時間の型と、起動・終了の条件
             ・強さ(Weak〜Strong。どれだけ確からしいか)と、裏取りの状況
             ・状態(待機/進行中/休眠/終了)
```

### 4.1 テーマ

- 何年も続く大きな流れ(AI、半導体、防衛など)は**テーマ**として扱う。良いニュースも悪いニュースも出続けるので、期限を持たせない。
- テーマが持つのは**温度**と**前提カード**だけである。
- テーマに関するニュースの多くは、温度を更新するだけで終わる。シナリオを立てるのは、前提を超えるサプライズ(§5)が出たときだけである。これで、巨大なテーマのニュースに振り回されずに済む。
- テーマの一覧は `THEMES.md` にある(戦略17分野、財政・税・金融、市場テーマ、局面展開型のひな形)。

### 4.2 シナリオ(すべての中心)

- **ニュース**は、シナリオを**生む・強める・弱める・終わらせる**材料である。
- **候補銘柄**は、必ずどれか1つのシナリオに属する。
- **評価もシナリオ単位**で行う。同じシナリオから出た候補は値動きが連動するので、独立に数えない。
- 同じ仮説が新しい事実で段階的に強くなっていく流れは、シナリオの一生として扱う(例:不祥事 → スポンサー離れ → 株主提案 → 大量保有報告書)。
  - 強化として数えるのは、**新しい事実**が加わったときだけとする。同じ事実の繰り返し報道は、強化ではなく注目度の増加である。
  - LLM は自分の仮説を強める方向に読みがちである。そのため、強化と弱体化の両方の読み方を必ず出させる。

### 4.3 シナリオの時間の型

ニュースの賞味期限は事例によって違う。日数で一律に決めず、シナリオを立てるときに**時間の型**を決める。

| 時間の型 | 例 | 時計の動き方 |
|---|---|---|
| **単発型** | 提携、受注、不祥事、大量保有報告書 | 初報から時計が動く。想定期間は短い |
| **局面展開型** | 大地震、感染症、戦争、政変 | 局面ごとに時計を持つ。次の局面の**起動条件**を満たすまでは**待機**で、時計は止まっている |
| **予定日型** | 選挙、政策の施行日、大型の催事 | 予定日に向けて動き、予定日の数日後に終わる |

南海トラフ地震の例:

```
局面1 パニック   全面安。防災用品などの即時のシナリオだけが進む
  │ 起動条件:市場の下げ止まり、または政府の復興予算の報道
  ▼
局面2 冷静化     「復興需要」シナリオが待機から進行中へ。ここから時計が動く
  │ 起動条件:補正予算の成立、発注の開始
  ▼
局面3 実需       受注や業績の上方修正。シナリオの強化として扱う
```

- 起動条件と終了条件は、シナリオを立てたその日のうちに記録し、後から都合よく変えない。
- 局面展開型は、`THEMES.md` のひな形を初期値として使い、当日の状況に合わせて確定する。

## 5. 反応すべきニュースの見分け方(粒度の核心)

### 5.1 鮮度はテーマではなく「事実」に付く

AI というテーマは古い。しかし「TSMC が来年の発注を100倍にする」という**事実**は新しく、しかも市場の想定を桁違いに超える。株価を動かすのはテーマの新しさではなく、**市場の想定からのズレ(サプライズ)**である。

反応すべきかどうかは、**そのニュースが、市場が今織り込んでいる前提をどれだけ裏切るか**で決める。

### 5.2 前提カード:サプライズを測る基準線

```
テーマ:AI・データセンター   前提カード v7
 ・市場の前提:大手のデータセンター投資は年 +30% 程度の成長が続く
 ・注目の数字:大手クラウドの設備投資額、TSMC の先端品の生産能力
 ・前提を崩す方向:投資の急減速、規制、電力不足
```

- 前提カードは、**そのテーマで初めて S・A級の判定が出るときに作る**。全テーマ分を先に作ることはしない。
- そのときは、ニュースを見る前の市場の想定を先に書き出して前提カード v1 とし、それを基準に等級を付ける。
- 版を管理し、どの版を基準に判定したかを記録する。

### 5.3 4つの等級

| 等級 | 意味 | 扱い |
|---|---|---|
| **S スーパーサプライズ** | 前提そのものが変わる(数字の桁が変わる、制度が変わる) | 必ず処理する。テーマが古くても、鮮度100%のシナリオを立てる |
| **A サプライズ** | 前提の範囲を明確に超える | シナリオを立てるか、既存のシナリオを強化する |
| **B 想定内** | 既知の流れが続いているだけ | シナリオは立てない。テーマの温度を更新するだけ |
| **C ノイズ** | 新しい事実がない(論評、繰り返し報道) | 記録するだけ |

**等級を決める4つの質問**

1. **新しい事実か**:過去の報道や観測記事に同じ内容がないか
2. **前提からどれだけ離れているか**:前回の数字や会社の計画と比べて何倍か。数字を並べて示す
3. **誰が、どれだけ確定的に言ったか**:公式発表か噂か。当事者は業界の中心企業か
4. **市場は実際に驚いたか**:1段目の銘柄の値動きが、普段の値動きの何倍か(Python による客観的な検算)

**等級は2段階で決める。** 夜の時点では、夕方の開示や米国企業のニュースに対する株価の反応がまだ出ていない。

- 夜:LLM が質問1〜3で**暫定の等級**を付ける。
- 翌日:Python が質問4で検算し、**確定の等級**にする。LLM が S級と判定しても1段目が動かなければ等級を下げ、B級と判定しても1段目が大きく動いていれば見落としとして知らせる。

米国企業の発表なら、日本の寄り付き前に米国市場での反応が分かる。翌朝、Python が自動で確認して、大きく動いていれば知らせる(人の作業は増やさない)。

### 5.4 テーマの温度とサプライズ

- **熱いテーマの良いニュース**は、想定内になりやすい(市場がすでに期待している)。
- **冷えたテーマの良いニュース**や、**熱いテーマの悪いニュース**は、同じ大きさでもサプライズになりやすい。

### 5.5 新しいテーマ

実際には、**既存のテーマ × サプライズ**の組み合わせが大半である。新しいテーマが生まれるのは年に数回程度と考える。

- 専用の大きな仕組みは作らない。**どのテーマにも当てはまらない S・A級のニュース**に「新テーマ候補」の目印を付けるだけとする。
- 目印の付いたシナリオは、前提カードがまだない(= 市場が何も織り込んでいない)ことを、想定上昇幅を見積もるときの根拠として明記する。一律の上乗せはしない。
- 定着したら `THEMES.md` に追加する。

### 5.6 量より質

すべてのニュースに連想をかけるとキリがない。LLM に渡す前に、Python で機械的に絞る。

```
ニュース           数百〜数千件/日
  ↓ 同じ出来事の記事をまとめる
イベント候補       数十件/日
  ↓ 注目度・新規性・開示の種類で足切り(Python)
LLM に渡すイベント  0〜3件/日(進行中シナリオに関係するものは別枠)
  ↓ 等級を付け、S・A級だけでシナリオを立てる
本命               0〜3銘柄/日  ←「今日は該当なし」を正常な結果とする
```

## 6. 連想と過去事例

### 6.1 連想の2つの視点

| 視点 | 問い | 裏付けの材料 |
|---|---|---|
| **経済的なつながり** | 実際に利益に効くか | 有価証券報告書のセグメント・取引先・原価構成 |
| **投資家の連想** | 投資家はこのニュースで何を思い浮かべるか | テーマの分類、過去事例、報道の見出し |

市場が乗る連想と、経済的に正しい連想は別物である。儲けの源泉は前者だが、後者の裏付けのない連想は崩れやすい。両方の視点で候補を出し、どちらから出た候補かを記録する。

### 6.2 過去事例ライブラリ(中核)

**大衆は過去の反応を参考に売買する。** 「前回の地震では建設株が上がったから今回も」という連想そのものが、株価を動かす。過去の反応は、投資家の連想の元ネタそのものである。

- **中身**:過去の大きなニュースごとに、関連銘柄の反応を記録する。
  - 何日後に動いたか、どれだけ上がったか
  - **動かなかった関連銘柄**も必ず記録する(上がった例だけを集めると、材料の大きさを過大に見積もる)
- **使い道**:シナリオを立てるとき、似た過去の事例を引いて、次の根拠にする。
  - 材料の大きさ(想定上昇幅)
  - 時間の型(反応までの日数)
  - 投資家が連想しそうな銘柄
- **作り方**:値動きは Python が株価データから客観的に計算する。どの銘柄が関連するかや、事例の説明は LLM が補う。
- 過去から学ぶことは積極的に行う。ただし、過去の事例を LLM に解かせて「当てられた」としても、それを探す能力の証明には数えない(LLM は結末を知っているため。§10)。

## 7. 裏取り調査

**自信を高めるのは、連想そのものではなく、連想の各段階を事実で確かめる調査である。**

### 7.1 確認計画

シナリオを立てるとき、連想の矢印ごとに「何を見れば確かめられるか」を決める。

例:「猛暑 → 不作 → 米価の上昇 → 関連銘柄が買われる」

| 矢印 | 確かめる指標 | 情報源の例(無料) | 確認できたと言える基準 |
|---|---|---|---|
| 猛暑が続くか | 気温の実績と予報 | 気象庁の観測データ、1か月・3か月予報 | 主産地で平年より高い予報が続く |
| 不作になるか | 作柄 | 農林水産省の作柄の公表、産地の報道 | 主産地で「やや不良」以下 |
| 米価が上がるか | 販売価格 | 農林水産省の取引価格、店頭価格の調査 | 前年比で明確に上昇 |
| 会社に効くか | 業績への影響 | 有価証券報告書、月次売上 | 関連事業の売上比率が大きい |

- 確認計画は、シナリオを立てたその日のうちに記録する。後から作ると、結果を見て都合の良い指標を選べてしまう。
- 矢印ごとに「✓ 確認済み / ✗ 否定 / 未確認」を持たせる。
- **反証も必ず調べる**(例:在庫が十分にある、輸入で補える、備蓄米の放出)。打ち消す事実が見つかれば、実現確度を下げる。

### 7.2 裏取りをするのは、新しい情報が出たときだけ

毎日の裏取りはしない。裏取りをするのは次の3つの時点だけである。

1. シナリオを立てたとき
2. そのシナリオに関係する新しいニュースが出たとき
3. 確認計画で決めた統計の公表日(統計の公表も新しい情報である)

その夜に深く調べるのは、ランキング上位の1〜2件だけとする。残りは翌日以降に回す。

### 7.3 証拠の扱い

- 証拠として記録するのは、**URL・取得時刻・値**がそろったものだけとする。LLM の推論は証拠にしない。
- 証拠には**情報源の信頼度**(4段階)を付ける。

| 段階 | 情報源 |
|---|---|
| 1 | 公的統計、適時開示(TDnet)、EDINET |
| 2 | 大手の報道機関 |
| 3 | 業界紙・専門メディア |
| 4 | 個人ブログ、掲示板、まとめサイト、SNS |

- **段階3・4の情報源だけで成り立つ矢印は「未確認」扱い**とする。「まだ誰も気づいていない狙い目」ほど情報源が薄く、デマや仕手の領域に近いためである。
- 繰り返し使う指標(気温、米価、電力需給、為替、商品価格など)は**指標ライブラリ**に登録し、次回から探し直さずに済むようにする。

## 8. 判断の物差しとランキング

### 8.1 3つの物差し

| 物差し | 意味 | 求め方 |
|---|---|---|
| **鮮度** | 材料がまだ新しいか | シナリオの起動日を100%とし、想定期間に対する経過の割合で減らす。待機中は減らさない。新しい事実で強化されたら、その日を起点に戻す |
| **材料の大きさ(想定上昇幅)** | この材料で最終的にどこまで上がり得るか | 幅で推定する(例:+20〜60%)。代表値は中央値とする。根拠は、ニュースの等級、影響額と時価総額の比、過去事例の上昇幅、時価総額の小ささ |
| **織り込み度** | 想定上昇幅のうち、どこまで株価が動いたか | 起動日の前日終値からの、TOPIX に対する超過上昇 ÷ 想定上昇幅(中央値) |

- ストップ高まで上がっても、材料が強烈で3倍になり得るなら、織り込み度はまだ低い。逆に、少ししか上がっていなくても、材料が小さければ織り込み度は高い。
- 想定上昇幅を見直したときは、新しい版として記録する。振り返りは、最初の見積もりの版で行う。
- **シナリオが強化されたときに変わるもの**:鮮度はその日を起点に戻り、想定期間もその日から数え直す(終了の判定が延びる)。想定上昇幅は必要なら新しい版にする。**変わらないもの**:織り込み度の起点(起動日の前日終値)と、「動いた」の判定の期間(本命に挙げた日から数える)。評価の基準を後から動かさないためである。
- 用語:**シナリオの強さ**(Weak〜Strong)は「どれだけ確からしいか」、**材料の大きさ**(想定上昇幅)は「当たればどれだけ上がるか」を表す。局面展開型の**局面**とも区別する。

### 8.2 反応の診断:未発見か、材料が弱いか

市場が反応しないこと自体が、材料の大きさについての情報である。

**注目度と株価の反応の組み合わせ**

| | 株価が反応した | 株価が反応しない |
|---|---|---|
| **注目度が高い**(広く知られている) | 織り込みが進んでいる → 残り余地を見る | **⚠ 無視されている** → 市場が弱い材料と判断した疑い |
| **注目度が低い**(まだ知られていない) | 早耳筋が先回りしている → 追随するか要判断 | **未発見** → 狙い目の候補。ただし広がるきっかけが必要 |

**1段目と2段目の反応の組み合わせ**(優位性①に直結)

| 1段目の銘柄 | 2段目(候補)の銘柄 | 診断 |
|---|---|---|
| 反応した | まだ反応していない | **時間差あり** ― 最も狙いたい状態 |
| 反応した | 反応した | 織り込みが進んでいる → 残り余地を見る |
| 反応していない | 反応していない | **材料そのものが弱い疑い** |

### 8.3 シナリオの終了

シナリオ自身の時計(§4.3)で判定する。

| 条件 | 終了の理由 |
|---|---|
| 起動後、想定期間を過ぎても1段目・2段目とも反応しない | 材料が弱かった |
| 起動後、1段目は反応したが、想定期間を過ぎても2段目が反応しない | 連想が市場に届かなかった |
| 織り込み度が80%以上 | 織り込みが完了した |
| 終了条件に当たった | シナリオが崩れた |
| 起動条件を満たさないまま60営業日たった | 起動しなかった(スイングの対象外) |

終了したシナリオも記録として残し、月次の振り返りに使う。

### 8.4 自信度ランキング

**上位ほど自信がある順**に並べる。考え方は「当たる確率 × 当たったときの残りの取り分」である。

```
自信度 = 実現確度 × 残り余地 × 鮮度の補正

  実現確度 = シナリオが実現して株価が動く確率(LLM が推定)。次で上げ下げする
             ・シナリオの強さ(Weak〜Strong)
             ・ニュースの大きさ(注目度。世の中が騒ぐニュースほど素直に反応する)
             ・裏取りの進み具合(矢印のうち、事実で確認できた割合)
             ・反証の調査の結果
             ・方向の明確さ(プラスにもマイナスにも読めるものは下げる)
             ・反応の診断(「無視されている」は大きく下げる)
             ・テーマの温度(追い風なら上げ、逆風なら下げる)
             ・似た過去事例の結果
  残り余地 = 想定上昇幅 × (1 − 織り込み度)
  鮮度の補正 = 古い材料ほど下げる
```

- ランキングの対象は、その日のニュースだけでなく、**進行中の全シナリオの候補**とする。
- 上位3件までを**本命**、それ以下を**監視**とする。
- **本命にしない銘柄**:流動性の下限を満たさないもの、監理・整理ポストの銘柄、極端な低位株、直近ですでに急騰したもの、裏取りの証拠が信頼度3・4の情報源だけのもの。
- ★の数は、自信度を固定の閾値で4段階に分けて表示する。
- 計算式の重みは暫定である。単純な掛け算で始め、振り返りで見直す。

### 9.1 O1 連想レポート

```

■ 今日の結論:本命 2銘柄 / 新しいシナリオ 1件 / 強化 1件 / 終了 1件

│ 等級      :A(暫定。翌日に確定)  背景テーマ:半導体(温度 上昇中 → 追い風)
│ 連想の道筋:ニュース → 1段目(大手、すでに +15%) → 2段目(この銘柄、+3%)

  ・#12「アクティビスト介入」 強さ Weak+ → Medium に強化(株主提案の報道)
```

  - シナリオが弱体化・消滅した(悪材料)
  - 織り込み度が70%以上(完了が近い。80%で終了)
  - 想定期間の終わりが近い(残り2営業日以下)
- 「あなたの判断」の欄は任意である。書いた場合は記録し、振り返りに使う。

### 9.2 O2 振り返りレポート(月1回)

目的は点数付けではなく、**探す能力を上げる改善点を見つけること**である。

1. **見逃し**:S・A級のニュースのあと、実際に大きく動いた関連銘柄のうち、候補に挙げていなかったもの。なぜ連想できなかったか。
2. **外れ**:本命に挙げたのに動かなかったもの。連想のどの矢印が間違っていたか。
3. **3つの指標**:的中率(偶然の場合との比較つき)、捕捉率、先行性。**1段目の銘柄だけを挙げた場合**とも比べる(2段目の連想に価値があるかの確認)。
4. **改善の実行**:見逃しと外れから、次のどれを直すかを決める。
   - 連想の指示文
   - 前提カード
   - 等級の基準
   - 過去事例ライブラリへの追加
5. 運用の状況:実行した日数、平均の作業時間、実行しなかった日の理由。

- 最初の数か月は件数が少ない。**月次のレポートでは合否の判定をしない**。判定は §11 の時期に、まとめて行う。

列:日付、銘柄コード、社名、シナリオ番号、自信度、崩れる条件。既存システムは、このファイルを読むだけで連携できる。

## 10. 検証の考え方

| 使い方 | 例 | 扱い |
|---|---|---|
| **過去から学ぶ** | 「前回の地震のあと、復興銘柄は何日後にどれだけ上がったか」 | **積極的に行う**(過去事例ライブラリ) |
| **Python だけで決まる判定を過去データで検証する** | 「注目度が高いのに反応しない銘柄は、その後も動かないか」 | 行ってよい(LLM が関わらないため) |
| **LLM の連想の精度を過去のニュースで測る** | 「当時このシステムを使っていたら当てられたか」 | 能力の証明には数えない(LLM が結末を知っているため)。連想の精度は、これから記録する実運用の結果で測る |

- 記録は追記だけにし、書き換えない。候補にしなかった銘柄や、落としたイベントも残す。
- 「動いた」の定義、閾値、合格の基準は、運用開始前に分析計画(`ANALYSIS_PLAN.md`)で固定する。結果を見てから変えない。変えるときは日付と理由を残し、変更の前後を混ぜて評価しない。

## 11. 成功と撤退の基準

| 段階 | 基準 | 判定の時期 |
|---|---|---|
| **L1 運用が回る** | 毎晩の作業が30分以内に収まり、3か月間ほぼ毎日続く | 運用開始から3か月 |
| **L2 探す能力がある** | 的中率が偶然の場合を上回り、捕捉率・先行性とあわせて、1段目だけを挙げる場合より価値があると言える | 独立したシナリオが60件たまった時点(目安6か月) |

- L2 の結論は「**ある/ない/保留(件数が足りない)**」の3つとする。
- L1 が成り立たなければ、作業を簡略化する。L2 が「ない」なら、中止するか方針を転換する。
- 売買の成績(実際に儲かったか)は、本プロジェクトでは評価しない。

## 12. 役割分担と毎日の流れ

### 12.1 役割分担

| 担当 | やること | やらないこと |
|---|---|---|
| **Python(自動)** | 収集、足切り、注目度・株価の計算、時刻の記録、銘柄の照合、等級の検算、ランキングの計算、売りのサインの検出、振り返りの集計 | 解釈、連想 |
| **LLM(Claude Code・手動で1日1回)** | 等級付け、シナリオを立てる・更新する、連想する、確認計画と裏取り、反証、過去事例の参照、前提カードとテーマの温度の更新 | 時刻や数値を決めること、記録の確定 |
| **あなた** | レポートを読んで判断する。任意で判断を記録する。週1回、人気テーマに未登録のものがないか確認する | 毎日すべてを読むこと |

**原則:事実と数字は Python、発想は LLM、最終判断はあなた。**

### 12.2 毎日の流れ(これ以上増やさない)

```
夕方 [自動]  収集・足切り・株価の計算
夜   [手動]  ① 選ぶ    等級を付け、S・A級だけを残す              → 0〜3件
             ② 立てる  シナリオを立てる・更新する。確認計画を記録し、上位は裏取りする
             ③ 絞る    ランキングを計算し、本命を出す             → 0〜3銘柄
     [自動]  ④ 記録    すべて追記で確定し、レポートを作る
翌朝 [自動]  米国市場の1段目の反応を確認し、大きければ知らせる
翌日 [自動]  ⑤ 更新    等級の確定、織り込み度・鮮度・終了判定、売りのサイン
```

- 作業時間は**1日30分以内**とする。守るために次の3つを決める。
  - 進行中・待機中のシナリオは**最大15件**。超えたら自信度の低いものから休眠にする。
  - 裏取りは、その夜は上位1〜2件だけとする。
  - 時間がない日のための**最小手順(10分)**を用意する(進行中のシナリオの更新と、最大の1件だけを処理する)。
- 実行しなかった日も、収集は自動で続ける。実行の有無と理由は記録する。

## 14. 作る順番

### 14.1 初日から必須(後から取り戻せないもの)

| 項目 | 理由 |
|---|---|
| ニュース・TDnet・上場銘柄一覧の収集 | 無料データは過去分が消える(TDnet は約1か月) |
| 時刻の記録(いつ知り得たか。保存は UTC、営業日は日本時間) | 後から正確に復元できない |
| シナリオ・候補・ランキングの追記専用の記録(落としたイベントや候補も含む) | 後から作ると、結果を見た後付けになる |
| 確認計画と裏取りの結果の記録(URL・取得時刻・値・信頼度) | 後から作ると、都合の良い指標を選べてしまう |
| 使ったモデルと指示文の版の記録 | モデルが変わった前後を区別できなくなる |
| 候補に使った銘柄の株価の複製 | 上場廃止すると yfinance からデータが消える |
| 実行の記録(実行したか、所要時間、理由) | L1 の判定に必要 |
| 分析計画(`ANALYSIS_PLAN.md`)の固定 | 運用開始後に作ると、結果に合わせた基準になってしまう |

### 14.2 それ以外は、必要になってから作る

次の表の条件に当たったときだけ作る。一度も作らずに終わるものがあっても構わない。記録さえ残っていれば、分析は必要なときに Claude Code でその場で行える。

| 機能 | 作るのはこういうとき |
|---|---|
| テーマの温度の自動計算 | LLM による週1回の判定がぶれる、または手間が大きい |
| 指標の自動取得 | 同じ指標を手作業で3回以上調べた |
| 説明のつかない連れ高の自動検出 | 新しいテーマを後から知ることが続く |
| 足切りで落としたイベントの抜き取り検査 | 見逃しの原因が足切りだと分かることが続く |
| 出力のばらつきの測定 | 同じ状況で候補が毎回大きく変わる気がする |
| 既存システムとの自動連携 | CSV を手で開いて確認する手間が大きい |

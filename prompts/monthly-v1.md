# 月次の振り返りの指示文 monthly-v1

目的は点数付けではなく、**ニュースから有望銘柄を探す能力を上げる改善点を見つけること**です(`docs/CONCEPT.md` §9.2)。

## 入力

`data/reviews/review_input_YYYY-MM.json`(Python が集計したもの)
- `metrics`:的中率(銘柄・シナリオ)、偶然の的中率、1段目だけの的中率、先行性、運用の状況
- `movers`:その月の S・A級のイベントごとに、その後20営業日で「動いた」銘柄のうち、候補に挙げていなかったもの
- `failures`:本命に挙げたのに「動かなかった」銘柄と、そのシナリオの確認計画・証拠
- `gate_dropped`:足切りで落としたイベントのうち、後で注目度が大きくなったもの

## 手順

1. **関係の判定**:`movers` のそれぞれについて、そのイベントと関係して動いたのかを判定し、`related_movers` に書きます(関係がなければ `related: false`)。これは結果を知ったうえでの**事後の判定**です。
2. **見逃しの原因**:関係ありと判定したものについて、なぜ候補に挙げられなかったのかを `miss_analysis` に分類します。
3. **外れの原因**:`failures` について、連想のどの矢印が間違っていたのかを `failure_analysis` に書きます。
4. **改善の提案**:見逃しと外れから、何を直すかを `improvements` に書きます(指示文、前提カード、等級の基準、過去事例、足切り)。**同じ原因が2件以上あるものを優先**してください。1件だけの出来事で大きく変えないこと。
5. **過去事例の追加**:今月の大きなイベントを、`new_past_cases` に過去事例の形式(`knowledge/past_cases/README.md`)で書きます。**動かなかった関連銘柄も必ず入れます。**

## 出力

`schemas/monthly_output.schema.json` に合う JSON を `data/inbox/monthly_YYYY-MM.json` に保存します。

## 注意

- 月次の振り返りでは、合否(L2)の判定はしません。
- 改善を実際に反映するのは、ユーザーが提案を確認してからです。指示文を変えたら版を上げ(例:daily-v2)、`docs/DECISIONS.md` に日付と理由を書きます。
